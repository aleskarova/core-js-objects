# Разбор рефакторинга `src/objects-tasks.js`

По каждой задаче: что было, что стало и почему. Ограничения, которые влияли на выбор:

- линтер `airbnb-base` + `prettier`, инлайн-отключения правил запрещены (`noInlineConfig`);
- блок тестов «optimal implementation» проверяет, что в тексте функции есть конкретное слово (`assign`, `entries`, `delete`, `keys`, `freeze`);
- правило `max-classes-per-file` разрешает один класс на файл.

## Без изменений

### `shallowCopy`

```js
const copy = {};
return Object.assign(copy, obj);
```

Идиоматичный вариант — `{ ...obj }`, но тест требует слово `assign`. Самая короткая запись `Object.assign({}, obj)` запрещена правилом `prefer-object-spread`. Промежуточная переменная — единственный способ удовлетворить и тест, и линтер, поэтому код оставлен как есть.

### `isEmptyObject`, `makeImmutable`, `getJSON`

Однострочники через `Object.keys`, `Object.freeze` и `JSON.stringify` — улучшать нечего.

## Изменено

### `mergeObjects`

```js
const merged = {};
objects.forEach((obj) => {
  Object.entries(obj).forEach(([key, value]) => {
    merged[key] = (merged[key] ?? 0) + value;
  });
});
return merged;
```

- `reduce` здесь не сворачивал значения, а мутировал один и тот же аккумулятор. Это обычный цикл, замаскированный под `reduce`, и `forEach` говорит об этом честно.
- Пропала переменная `curMerged`, которая существовала только ради обхода `no-param-reassign`.
- Ветка `if/else` заменена на `(merged[key] ?? 0) + value`: «возьми текущее значение или ноль и прибавь».
- Убрана лишняя переменная `mergedObject` перед `return`.

### `removeProperties`

```js
const result = { ...obj };
keys.forEach((key) => {
  delete result[key];
});
return result;
```

**Поведение изменилось:** раньше функция мутировала переданный объект, теперь возвращает копию.

- `const object = obj` не создавал копию, а только прятал мутацию аргумента от линтера. Читатель видит новое имя и ожидает новый объект.
- Функция, которая возвращает результат, не должна заодно портить вход: вызывающий код не ждёт, что его объект изменится.
- Если по замыслу задачи нужна именно мутация исходного объекта, верните прежний вариант — тесты проходят в обоих случаях.
- Тело колбэка взято в фигурные скобки, чтобы стрелка не возвращала результат `delete`, который никому не нужен.

### `compareObjects`

```js
return (
  keys1.length === keys2.length &&
  keys1.every((key) => Object.hasOwn(obj2, key) && obj1[key] === obj2[key])
);
```

Исправлена ошибка: `compareObjects({ a: undefined }, { b: 1 })` возвращал `true`. Длины совпадают, а `obj2.a` — это `undefined`, как и `obj1.a`. Проверка `Object.hasOwn` убеждается, что ключ действительно есть во втором объекте.

### `makeWord`

Алгоритм тот же, изменены только имена: `letter`, `positions`, `position` вместо `key`, `indexes`, `i`, и `letters` вместо `lettersArr`. Имена из предметной области читаются без оглядки на условие, а тип в имени (`Arr`) ничего не добавляет.

### `sellTickets`

```js
let bills25 = 0;
let bills50 = 0;

return queue.every((bill) => {
  if (bill === 25) {
    bills25 += 1;
  } else if (bill === 50) {
    bills50 += 1;
    bills25 -= 1;
  } else if (bills50 > 0) {
    bills50 -= 1;
    bills25 -= 1;
  } else {
    bills25 -= 3;
  }
  return bills25 >= 0;
});
```

- Счётчик сотенных купюр убран: ими никогда не дают сдачу.
- Вместо проверки «хватит ли» перед каждой выдачей сдача выдаётся сразу, а в конце шага одна проверка: число купюр по 25 не ушло в минус. Купюра 25 участвует в любой сдаче, поэтому одной проверки достаточно.
- `every` выражает смысл задачи напрямую («каждому в очереди можно продать билет») и сам останавливается на первом `false`.
- Вложенность сократилась с трёх уровней до одного.

### `Rectangle`

```js
function Rectangle(width, height) {
  this.width = width;
  this.height = height;
}

Rectangle.prototype.getArea = function getArea() {
  return this.width * this.height;
};
```

- Раньше конструктор возвращал объектный литерал, поэтому `new Rectangle(...) instanceof Rectangle` был `false`, а `new` фактически ничего не делал.
- `getArea` считал площадь по замыканию на аргументы конструктора. После `r.width = 5` площадь оставалась старой. Теперь метод читает `this.width` и `this.height`.
- Метод лежит в прототипе и не создаётся заново для каждого экземпляра.
- Современная запись — `class Rectangle`, но в файле уже есть класс `Selector`, а линтер разрешает только один. Функция-конструктор с прототипом — то же самое по поведению.

### `fromJSON`

```js
return Object.assign(Object.create(proto), JSON.parse(json));
```

`Object.setPrototypeOf` на уже созданном объекте MDN прямо не рекомендует: движки оптимизируют объекты под их прототип, и его смена эти оптимизации сбрасывает. Правильнее сразу создать объект с нужным прототипом через `Object.create` и скопировать в него поля.

### `sortCitiesArray`

```js
return arr.toSorted(
  (a, b) => a.country.localeCompare(b.country) || a.city.localeCompare(b.city)
);
```

- `localeCompare` возвращает отрицательное число, ноль или положительное — ровно то, что нужно компаратору. Ручные `if (<) return -1; if (>) return 1` не нужны.
- `||` даёт сортировку по второму ключу: если страны равны, первое сравнение даёт `0` (ложное значение), и результатом становится сравнение городов.
- **Поведение немного изменилось:** раньше строки приводились к верхнему регистру и сравнивались по кодам символов, теперь сравниваются по правилам локали. Для имён собственных это корректнее (например, буквы с диакритикой встают на своё место), на тестовых данных результат тот же.
- `toSorted` оставлен: он не мутирует входной массив.

### `group`

```js
const groups = Map.groupBy(array, keySelector);
return new Map(
  Array.from(groups, ([key, items]) => [key, items.map(valueSelector)])
);
```

- `Object.groupBy` заменён на `Map.groupBy`, раз результатом должен быть `Map`. Не нужен промежуточный объект и `Object.entries`.
- У `Object.groupBy` два побочных эффекта, которых у `Map.groupBy` нет: ключи приводятся к строкам, а ключи, похожие на целые числа, переставляются в начало. Для ключей-стран это не проявлялось, но функция принимает произвольный `keySelector`.
- Имена `country`, `cities` заменены на `key`, `items`: функция обобщённая и о странах ничего не знает.
- Исправлена опечатка `groupped`.

### `cssSelectorBuilder`

Общая схема сохранена: один класс `Selector`, один метод добавления части, фасад `cssSelectorBuilder`. Изменено следующее.

- **Таблица `SELECTOR_PARTS` вместо магических чисел.** Раньше порядок (`1`…`6`), признак уникальности и префикс были размазаны по шести методам в виде `this.append(`#${value}`, 2, true)`. Теперь всё описание грамматики селектора лежит в одном месте, и каждая строка читается как правило: порядок, уникальность, формат.
- **Убран `Set` уникальных частей.** Части добавляются только по возрастанию порядка, значит повторная уникальная часть — это всегда та же, что была добавлена последней. Достаточно сравнить `order === this.#lastOrder`. Это единственное неочевидное место, поэтому там оставлен комментарий.
- **Приватные поля и метод (`#value`, `#lastOrder`, `#append`).** Снаружи доступны только методы-части и `stringify()`. Раньше можно было вызвать `selector.append(...)` в обход проверок или перезаписать `selector.selector`.
- **`combine` возвращает объект только с `stringify()`.** Раньше он возвращал `Selector` со сброшенным состоянием, и к комбинации можно было дописать, например, `.element('div')` — получалась строка вроде `a + bdiv`. Отдельный класс для комбинации был бы аккуратнее, но упирается в то же правило «один класс на файл».
- **`combine` хранит ссылки на селекторы, а не готовую строку.** Строка собирается в момент вызова `stringify()`.
